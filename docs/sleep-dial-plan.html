1 · What's wrong today

The sleep button (and S) cycles SLEEP_PRESETS = [15, 30, 45, 60, 90, 120]: first press arms the default, each further press jumps to the next preset, and past 120 it wraps to off. Setting 2 h from cold is five presses; anything over 2 h or between presets is impossible; overshooting means cycling all the way around again.

2 · The new UX — try it

The moon button stops cycling and instead opens a sleep panel anchored above the OSD. The fast path survives: the first press still arms the default immediately — the panel just opens alongside, already set, so a second gesture (drag, scroll, arrows, digits) refines it. Left edge of the dial is Off; the readout always shows the real-world consequence: the wall-clock time the TV goes dark, and that it waits for the credits.

🖱 Interactive: click the moon (or press S) to open the panel · drag the dial · scroll the wheel over the panel, the moon, or the countdown chip · use Left/Right for ±5 min, Up/Down for ±30 · type digits like 135 for 2 h 15 m · 0 for off · Enter closes.

3 · Interaction map

S / moon click Opens panel. If disarmed, also arms the default (sleepTimerDefaultMin) — the one-tap fast path is unchanged. Closes panel (state already committed live).
Scroll wheel over moon / chip / panel Adjusts remaining time ±5 min without opening anything — the countdown chip is the feedback. Same; the dial and readout track it.
Drag on dial— Sets any duration 0–300 in 5-min detents. Dragging to the left edge disarms. Commits on release; readout previews during the drag.
Left/Right Seek / skip (unchanged). ±5 min. Captured by the panel — they must not fall through to skip-episode.
Up/Down—±30 min.
Digits 0–9— Typed minutes with a ~900 ms commit buffer: 90 → 90 min, 135 → 2 h 15. 0 alone → off. Clamped to 300.
Enter / Esc—Close the panel. Nothing to cancel — changes apply live, matching how volume works.
Chips— Off · After this ep · 30m · 1h · 2h · 3h · 5h. “After this ep” arms with 0 minutes — already-expired, so the arc-aware boundary stops playback when the current episode (or arc) ends.
Idle ~6 s—Panel auto-hides with the rest of the OSD chrome.

4 · Implementation plan

  1. Store: clamp + relative adjust — src/renderer/src/store.ts

    armSleep(minutes) already accepts arbitrary minutes; add a clamp(0, 300) and export SLEEP_MAX_MIN = 300 from src/shared/types.ts. Add adjustSleep(deltaMin) that shifts sleepUntil (remaining time), not sleepMinutes — extending a timer armed an hour ago must add to what's left, not to the original figure. Disarm when the result drops to ≤ 0 while unexpired. armSleep(0) (already-due) is the “after this episode” path and needs no new store logic.

  2. New SleepPanel component — src/renderer/src/components/SleepPanel.tsx

    Dial (reuse the existing Slider with step=5, max=300, onPreview/onCommit — same contract as the volume track), tick marks, chips, live readout (“1 h 35 m · off around 2:41 AM, after the credits”). Rendered inside .stage so it survives requestFullscreen(), styled on the up-next toast surface.

  3. Player wiring — src/renderer/src/screens/Player.tsx

    Delete SLEEP_PRESETS and cycleSleep; S/moon toggles the panel (arming the default on first open when disarmed). While open, route arrows/digits/Enter/Esc to the panel before the player's key handler — Right is skip-episode today, so this scoping is the one sharp edge. Add a wheel handler on moon, chip, and panel calling adjustSleep(±5). Tie the panel into the existing OSD idle-hide timer.

  4. Settings — src/renderer/src/screens/Settings.tsx

    Extend the default-duration control to 300 (replace the SLEEP_DURATIONS dropdown with a 5-min-step number input or the same dial). Delete the “must stay in step with SLEEP_PRESETS” comment — the coupling dies with the presets.

  5. Tests — tests/handoff.test.ts

    • Arm 300 min → survives multiple episode handoffs, sleeps after the unit that crosses expiry.
    • adjustSleep extends remaining time on a long-armed timer; shrinking below zero disarms.
    • armSleep(0) stops at the current unit's end — including mid-arc (blackout waits for the arc).
    • Clamp: armSleep(900) → 300.

  6. Docs — docs/ui.md, docs/playback.md

    Replace the cycle description with the panel + interaction map; note the “after this episode” chip's zero-minute mechanism.

5 · Edge cases & decisions

  • Live commit, no OK button. The panel edits the armed timer directly (like volume). Closing never discards — one less click, and the countdown chip always tells the truth.
  • Adjusting an armed timer is relative to now. The dial reopens showing remaining minutes (snapped up to 5), not the originally armed figure.
  • Expired-but-finishing state (“Sleeps 12:41”) keeps today's chip behavior; opening the panel from it re-arms from now.
  • Blackout interplay: unchanged — the panel is player chrome and never outlives leavePlayer/sleepNow.
  • Why 5-min steps, not 1: 61 detents keep the drag snappy on a ~420 px track (~7 px per detent) and nobody plans bedtime to the minute; typed digits still allow exact values if wanted later.
  • Out of scope, noted for later: “sleep after N more episodes” chips — the store's unit-boundary logic could support counting units instead of wall time.
