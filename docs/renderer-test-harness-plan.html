The gap this closes

Two bugs shipped past 300 green tests during the sleep-timer feature. Both lived in one React effect in Player.tsx — the branch that decides, when the timer has expired and the element reports paused, whether to call store.sleepNow(). The store’s transitions below that decision are pinned hard by tests/handoff.test.ts (real scheduler, real in-memory SQLite, seven sleep-timer cases) — but those tests call advance() / sleepNow() directly. The bugs were in which of those two the Player picks, and nothing in npm test renders the Player at all.

The two bugs, as measured

Both come from the same fact: paused === true does not mean a viewer pressed pause. The current fix keys the branch on viewer intent instead — wantsPlayRef is cleared only in togglePlay, the one place a human asks:

useEffect(() => {
  if (!sleepExpired || !paused || failed) return
  if (wantsPlayRef.current) return   // ← delete this line and every test today stays green
  void sleepNow()
}, [sleepExpired, paused, failed, sleepNow])

The approach: real Player, real store, two scripted seams

The handoff names the tension precisely: extracting the decision logic into a pure module risks a translation gap (the wiring was the bug), while a DOM emulator risks faking media semantics wrongly (a fake that fires ended without a preceding pause happily passes bug 1’s broken code). The plan threads it by rendering the real component and scripting only the two boundaries the repo already treats as contracts:

OptionVerdict
A · Extract decisions into a DOM-free module (the mse.ts pattern)Rejected as the primary move. The bugs were in the effect wiring — dependency arrays, ref reads, event-to-state timing. A pure function of (sleepExpired, paused, wantsPlay) would have been trivially correct while the real effect stayed broken. Player.tsx is left untouched; its four documented decisions stay where they are.

The scripted media model — measured, in one place

Everything the handoff warns a naive fake would get wrong is encoded once, in the harness, as named transitions with the citation attached. Tests never hand-fire raw events; they speak this vocabulary, so the next bug of this class gets its scenario by composing it — design for the class, not the four cases:

TransitionExactly what it does (and why)
endEpisode()On the active element: set ended = true and paused = true, dispatch pause in its own act() flush, then dispatch ended in the next — same tick, effects flushed between. This is the measured ordering (docs/playback.md § “Two things Chromium does around ended”) and the flush-between is what let the broken effect win live.
promotion (automatic)When the Player flips stage.active, the newly active fake reports paused = true, ended = false; its play() resolves on the following flush, then fires play. The transient window is therefore open across at least one effect pass — as it is in Chromium.
seek(seconds)Commits through the real scrub path; the reloaded stream presents the same transient-pause shape as a promotion before resuming.
viewerPause() / viewerPlay()Drives the real UI — the OSD play/pause button (or Space dispatched on document.body so the window key map sees an element target). This is what clears wantsPlayRef; the harness never touches the ref directly.
at(seconds)Fires timeupdate — how a test enters the T−30 s up-next window.
element.play()/pause()The app-facing element contract: pause() flips state and fires pause synchronously; play() returns a promise and fires play on resolution. volume/muted/currentTime are plain recorded fields.
failStream()Invokes onStreamError/onError — so the failed guard clauses stay expressible.

The four regression scenarios

ScenarioDriveAssertGoes red when…
1 · End-of-episode ordering (bug 1) Standalone deck → tune; expire the timer (sleepUntil in the past, as handoff.test.ts does); endEpisode(). reportEnded(ep, completed: true) exactly once, then blackout at the boundary. The sleepNow() shape — reportEnded(…, false) — never appears in the log. The branch keys on paused alone: the effect flush between pause and ended calls sleepNow() first, and the queue logs completed: false.
2 · Transient pause at a handoff (bug 2) 3-part-arc deck → tune (part 1); expire; store.prewarm() commits part 2 into the standby; endEpisode() → promotion. Screen stays 'player'; nowPlaying is part 2/3; the promoted element’s play() was requested; no reportEnded(part2, false), no blackout. The effect fires inside the promotion window (paused=true, ended=false) — including under the element.ended mutant that fixes only bug 1.
3 · A genuine viewer pause tune; viewerPause() (real button / Space); then expire the timer. sleepNow() path runs: reportEnded(ep, false), channel released, screen 'blackout', timer disarmed. The guard is over-strong — the paused branch can never fire at all (e.g. the whole effect deleted).
4 · Prewarm suppression Unit-final episode, timer expired; at(durationS − 25) enters the T−30 s window; then armSleep(null) to cancel. While expired: no prewarmNext call, pendingNext stays null. After cancel: prewarmNext fires — late but inside the window — exactly once (the deliberately-unset prewarmedAfterRef, Player.tsx ~430). The effect commits a pick for an episode nobody will watch, or the cancel path stops re-firing because the ref was set eagerly.

Scenario 1’s determinism is worth spelling out: with the guard reverted, the harness’s per-event flush makes the broken effect enqueue sleepNow() on the store’s serialize queue before handleEnded enqueues advance(true) — so the wrong log entry is produced every run, not one run in five. The mutation check below is the proof this modelling is faithful.

Typecheck ownership, decided deliberately

The handoff flags this and the repo’s split makes it sharp: tsconfig.node.json has no DOM lib (that’s the point — it is what keeps mse.ts and store.ts honest), and tsconfig.web.json has no Node types. The rule that resolves it: renderer tests are web code, so the web tsconfig owns them — and to stay ownable they must not import @main or better-sqlite3. That constraint is also the right test-design boundary: the scheduler-and-database truth is handoff.test.ts’s job, this layer’s job is which store action the Player invokes, and duplicating the real scheduler here would blur both.

Build order

  1. Walking skeleton — happy-dom + config edits; mount the real Player against the scripted bridge, tune, assert an episode is on air. Proves the react-dom/act/happy-dom/esbuild-JSX pipeline before any cleverness. Watch for the two known snags here: JSX transform in Vitest, and window-key events needing an element target.
  2. Vocabulary + scenario 3 — build FakeMediaElement/FakeVideoSurface; land the genuine pause case first. It has no ordering subtleties, so it isolates harness plumbing bugs from Chromium-model bugs.
  3. The bugs as tests — scenarios 1, 2 and 4, encoding the measured orderings.
  4. Mutation check + docs — the acceptance ritual below, then the development.md section, then npm test and npm run typecheck (both tsconfigs) clean.
  5. Optional complement — promote the sleep-timer --eval scenario that found these bugs into a checked-in scripts/soak-scenarios/ pack. Real-Chromium ground truth, runnable on demand, never part of npm test.

Acceptance bar — the mutation check is the point

A harness whose tests cannot fail on the original bugs is decoration, so the check is performed and its result stated in the implementation summary:

  • All four scenarios green in npm test, headless, no Electron, no display, added wall-clock in seconds.
  • Mutation 1: delete the wantsPlayRef.current guard line → scenarios 1 and 2 red; restore → green.
  • Mutation 2: replace the guard with if (video.ended) return (the plausible half-fix) → scenario 2 still red.
  • Mutation 3: delete the paused branch entirely → scenario 3 red (the guard is not over-strong).
  • Existing suite untouched and green; npm run typecheck clean on both tsconfigs, with the new files owned by tsconfig.web.json.
  • docs/development.md § Testing describes the layer: coverage, non-goals (real Chromium semantics stay with soak), and how to write the next test.

Risks & mitigations

RiskMitigation
act() flush order differs from Chromium’s real task boundariesThe harness dispatches each media event in its own flush — the interleaving measured live. The mutation check is the empirical proof: if the model were unfaithful, reverting the guard would not turn the tests red.
The fake surface drifts from the real VideoSurface contractIt implements the exported VideoSurfaceProps/VideoSurfaceHandle types, so contract changes fail typecheck in the harness the same day. The contract is narrow and documented (“forwarded only while active”); the real component’s logic-heavy half is already pinned by mse.test.ts, and real-Chromium behaviour stays soak-verified — the residual gap the handoff accepts.
happy-dom API gaps (fullscreen, PointerEvent details)The scenarios never enter fullscreen or drag sliders; keys are dispatched on document.body so e.target.closest exists. If a gap still bites in phase 1, jsdom is the drop-in fallback — the harness API doesn’t change.
Module-level state bleeding between testsSame discipline as handoff.test.ts: reset useStore.setState and swap globalThis.rerun in beforeEach; unmount in afterEach so the banner timeout and countdown interval are cleared by their own effects.
Wall-clock coupling (sleepUntil, nowMs)Expiry is a Date.now() comparison, so tests set sleepUntil in the past — the store design makes fake timers unnecessary; vi.setSystemTime stays available for a future countdown-crossing case.
Vitest JSX transform for .tsx testsesbuild’s automatic runtime is expected to apply; if not, one line in vitest.config.ts. Verified in the phase-1 skeleton, before anything depends on it.
