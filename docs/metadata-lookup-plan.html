Show metadata lookup

Select a show, type its name into a network-backed autocomplete, pick the match — the show gets a proper display title and every episode the provider knows gets its real title, joined on season × episode number. The first deliberate step past "the MVP has no network metadata lookups".

What the user gets

Today a show is titled by its folder (deriveShowTitle, src/main/library/parse.ts:133) and an episode by whatever trailing text survives cleanTitle (parse.ts:189) — often nothing, since release-style filenames like Gargoyles.S01E05.DVDRip.mkv carry no title at all. With this feature, the user selects a show in the Library, clicks Look up…, types a few characters into an autocomplete backed by TVmaze, and picks the right series from the candidate list. Applying the match sets a clean display title on the show (Gargoyles, not Gargoyles.1994.DVDRip) and fills in the real title of every episode the provider can pair with a local file by season and episode number — visible immediately in the Library, the Guide, and the Player overlay. The link is remembered, so newly scanned episodes can be titled later with one Refresh click, and Unlink puts everything back exactly as the scanner named it.

This reverses a documented non-goal — docs/architecture.md:214 lists external metadata as deliberately out of scope, and parse.ts:4 says the MVP has no network lookups. The reversal is intentional and narrow: titles only. Artwork, descriptions, and air dates stay out of scope.

The two constraints that shape the design

The scanner owns title and clobbers it on every rescan — so metadata gets its own columns.

upsertShow runs ON CONFLICT(folder_path) DO UPDATE SET title = excluded.title (src/main/db/repositories/library.ts:196) once per file per scan, and upsertEpisode sets title = excluded.title unconditionally (library.ts:301-306). Anything written into those columns dies on the next scan. The codebase already has the answer: part_group_id/part_index and the loudness columns are deliberately excluded from the upsert's SET list because the scanner "has no opinion" about them (doc comment at library.ts:276). Metadata follows the same pattern — shows.display_title and episodes.metadata_title are new columns the scanner never touches, and display falls back through COALESCE.

Keeping episodes.title untouched has a second payoff: auto-arc detection reads arc structure (Part 2, (1)…) straight off the scanner's stored title and re-runs on every scan (src/main/library/scanner.ts:475). Overwriting title with provider titles would silently change which arcs get detected. With a separate column, arcs are provably unaffected.

The renderer cannot call TVmaze — the lookup lives in the main process.

The renderer's CSP is connect-src 'self' http://127.0.0.1:* (src/renderer/index.html:20), so a fetch from the Library screen is a dead end by design. Both network calls go over IPC to a new main-process service modelled on the ffmpeg manifest client (src/main/services/ffmpeg-manager.ts:177-226): Electron's net.fetch (follows the app's proxy settings), AbortSignal.timeout, a deps seam so tests inject a fake network, and network errors surfaced as readable messages rather than retried silently.

Provider: TVmaze

TVmaze is the only mainstream TV metadata API that needs no API key, no account, and no OAuth — the right fit for a single-user desktop app that should work the moment it's installed. Licensing is CC BY-SA (an attribution line in the lookup panel covers it). TMDB and TVDB both gate episode data behind per-user API keys and are listed as future providers, not alternatives worth the setup friction now. The metadata_source column exists so a second provider can be added without a migration.

CallEndpointUsed for
Show search GET api.tvmaze.com/search/shows?q=<query> Autocomplete candidates. Response is scored fuzzy matches; the service maps each to { providerShowId, name, premiered, network, status } — year and network are what lets the user tell Gargoyles (1994) from The Goliath Chronicles (1996).
Episode list GET api.tvmaze.com/shows/:id/episodes?specials=1 The full episode list for the chosen series: { season, number, name } per entry. Fetched once at preview time; entries whose season or number is null (unnumbered specials) are dropped before the join.

TVmaze rate-limits at roughly 20 requests per 10 seconds. A 300 ms typeahead debounce with single-flight (a new keystroke aborts the in-flight search) keeps one user far under that; a 429 surfaces as an inline "TVmaze is rate-limiting — try again in a moment", never a retry loop.

The lookup flow

Preview and apply are split so that what the user saw is exactly what gets written: preview computes a MetadataPlan (every episode id and the title it would receive) and returns it without writing; apply takes that plan back and writes it in one transaction. No refetch between look and commit, so the provider changing under us can never make the apply differ from the preview.

Join semantics — what happens to each file

The join is deliberately dumb: a local episode pairs with the provider entry at the same (season, episode), using the numbers the scanner already parsed (parseEpisodeFilename, src/main/library/parse.ts:100) and the existing idx_episodes_show(show_id, season, episode) index. No fuzzy title matching, no air-date heuristics — files whose numbering doesn't line up are simply left alone, and the preview says so before anything is written.

Data model

Four nullable columns, appended as migration 8 to MIGRATIONS (src/main/db/schema.ts:30 — append-only per the file's header). All NULL means "never looked up", which is exactly the state every existing row is in, so the migration needs no backfill. The columns are then excluded from the SET lists in upsertShow and upsertEpisode so a rescan cannot clobber them.

ColumnTypeMeaning
shows.display_titleTEXT NULLUser-approved title from the provider. NULL → fall back to the scanner's title.
shows.metadata_sourceTEXT NULL'tvmaze' for now; exists so a second provider is a value, not a migration.
shows.metadata_idTEXT NULLThe provider's show id. Together with source, this is what makes Refresh a one-click re-join instead of a re-search.
episodes.metadata_titleTEXT NULLProvider episode name (joined with " / " for spans). NULL → fall back to the scanner's title.

Repository additions (SQL stays in src/main/db/repositories/library.ts): setShowMetadata, setEpisodeMetadataTitles (batch, inside the apply transaction), clearShowMetadata (nulls all four columns for a show and its episodes — the whole of Unlink). toShow/toEpisode (library.ts:102) grow the new fields. No new settings: the provider is fixed, and there is no key to store.

IPC surface

Four methods in the library namespace, moving the three contract files in lockstep (src/shared/ipc.ts:36 → src/preload/index.ts:22 → src/main/ipc/handlers.ts:176) so typecheck failures walk the implementation to every site:

  • searchMetadata(query: string): Promise<MetadataCandidate[]> — read-only, network.
  • previewMetadata(input: { showId, providerShowId }): Promise<MetadataPlan> — read-only, network. The plan carries displayTitle, episodes: { episodeId, title }[], and the matched / multi / unmatched counts the preview UI shows.
  • applyMetadata(plan: MetadataPlan): Promise<void> — one transaction, no network. The handler validates the plan's episode ids still belong to plan.showId (a scan may have run since preview), drops any that don't, then broadcast(EVENTS.libraryChanged) push.
  • unlinkMetadata(showId: number): Promise<void> — clearShowMetadata + broadcast. Restores the scanner's naming completely.

Refresh needs no fifth method — it is previewMetadata with the stored metadata_id followed by applyMetadata, driven from the UI. New types (MetadataCandidate, MetadataPlan) live in src/shared/types.ts; stale test fakes surface automatically via makeBridge (tests/renderer/bridge.ts:26).

UI — the metadata card

The affordance lives in the selected show's aside (Library.tsx:393), as a card above the arcs panel — the aside is already the "everything about the selected show" surface, and a lookup panel needs more room than an inline row fold-out. Assembly is from existing precedents: the typeahead input is AddShowPanel.tsx:30-39 plus a debounce; commit/cancel keys follow ChannelFold.tsx:338-410; errors from main render inline and verbatim, per AssignPanel.tsx:76-89.

Edge cases, decided

ScenarioBehavior
Rescan after linkingNothing changes: all four columns are excluded from the upsert SET lists, mirroring the arc/loudness precedent (library.ts:276). This is the load-bearing decision — it gets a dedicated regression test.
New episodes scanned after linkingThey arrive with metadata_title = NULL and show filename titles. The linked card offers Refresh; the scanner itself never touches the network, so scans stay offline and fast.
Show folder renamed on diskA new folder_path is a new show row (identity rule, library.ts:180-184), so the link is gone — re-run the lookup. Accepted; folder renames already orphan channel lineups the same way.
Offline / TVmaze down / 429Search and preview fail with a readable inline error; nothing is written, the library is untouched. Apply needs no network at all, so a preview already on screen can always be applied.
Scan runs between preview and applyThe apply handler re-validates every episode id in the plan against plan.showId and drops rows that vanished — a stale plan can shrink, never corrupt.
Wrong series appliedRe-run the lookup — the new apply overwrites the old titles wholesale. Unlink is the full undo: all four columns NULL, scanner naming back everywhere.
Provider title collides with arc namingImpossible by construction: arcs read episodes.title, which metadata never writes. A provider title like "Awakening: Part One" appears in the Player but cannot create or dissolve an arc.
Anime / absolute numberingOut of scope. Files the parser couldn't number are in unmatched_files already; a provider-side absolute-order join is a future provider feature, not this one.

Explicitly out of scope

Artwork and posters, episode descriptions and air dates, movie metadata, additional providers (TMDB/TVDB — the metadata_source column leaves the door open), automatic lookup during scans (the scanner stays offline), title-based fuzzy matching for unparseable files (that's the unmatched_files assign flow), and absolute-order numbering. Auto-arc detection semantics are deliberately unchanged.

Decisions taken (flag if you disagree)

DecisionWhy · the road not taken
TVmaze, single providerKeyless and instant for a personal app. TMDB/TVDB would each make the user register for an API key before the feature does anything. metadata_source keeps them possible later.
New columns, not overwriting titleOverwriting is what the scanner clobbers and what arcs read. Separate columns make rescans safe and arcs provably untouched — at the cost of one COALESCE per read site.
Preview returns the plan; apply writes the planWYSIWYG commit, offline-safe apply, and the join becomes a pure function. The alternative (apply refetches) can write something the user never saw.
Refresh is manualThe scanner stays a filesystem-only, offline operation — a scan can never stall on the network or surprise-overwrite titles. One click after a scan is the trade.
Span titles joined with " / "A two-episode file gets both names. Storing only the first hides real information; the join marker matches how such files are commonly labeled.
Unlink is totalAll four columns NULL, one action, no partial states — the mental model is "back to exactly what the scanner named".
