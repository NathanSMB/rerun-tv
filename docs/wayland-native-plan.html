Rerun TV · Engineering plan · August 2026

One rule, no detour

The picture-in-picture window stays above full-screen games because KWin holds it in the Overlay layer — a server-side window rule that never asks the client anything. The XWayland relaunch, the boot cache, and the Settings toggle exist to work around a problem the rule already solves. This plan removes all three and installs the rule on every session type, X11 and Wayland alike.

CH·01

Why the detour can go

The current build layers two mechanisms. The XWayland relaunch (src/main/boot-config.ts) buys _NET_WM_STATE_ABOVE, which only clears normal windows. The KWin rule (src/main/kwin-rule.ts) forces the window into the Overlay layer, which clears everything — including the layer an active full-screen game occupies. The rule is enforced by the compositor and matches by title, so it works identically for a native Wayland window. Once it does the whole job, the relaunch does nothing but cost us crisp fractional scaling and per-monitor DPI.

Nothing a client asks for reaches Overlay. Only a compositor-side window rule assigns it — and a rule doesn’t care whether the window arrived over X11 or Wayland.

The plan, in order

PHASE 0 · GATEProve the rule catches a native Wayland window

The one untested assumption: Chromium’s Wayland PiP toplevel carries the title the rule matches on. Twenty minutes of manual testing gates everything below.

  • Launch the built app on native Wayland using the escape hatch that already exists (boot-config.ts:160 skips the relaunch when an explicit flag is passed — the rule stays installed): 
    env -u ELECTRON_RUN_AS_NODE rerun-tv --ozone-platform=wayland
  • Start an episode, pop out picture-in-picture, then inspect the floating window: 
    qdbus org.kde.KWin /KWin org.kde.KWin.queryWindowInfo  # then click PiP
    Record caption, resourceClass (the Wayland app_id), and layer.
  • Run a game full-screen. Confirm the PiP window stays visible on top.
  • Note where KWin places the window on open, and whether dragging it works — Wayland has no client positioning, so placement is compositor-chosen (feeds decision D3 below).
EXIT — PiP visibly above a full-screen game on native Wayland. If the caption differs from Picture in picture, record the real caption and app_id and carry the corrected match into Phase 1 — on Wayland the window does have a class (the app’s app_id), the handle X11 never offered. If no match works at all: stop here, keep the toggle, wait for Chromium to ship the xdg-pip protocol (KWin already supports it since Plasma 6.5).

PHASE 1Main process — delete the platform machinery

Everything that chooses, caches, or reports a window system goes. The rule install becomes unconditional.

  • src/main/boot-config.ts — delete the file. Its exports are the relaunch decision (ozonePlatformOverride, relaunchPlatform, isSupervisedRun), the boot.json cache, and the window-system report. All dead once nothing relaunches.
  • src/main/index.ts — remove the relaunch block (index.ts:49–102) and the relaunching branch in the single-instance gate (index.ts:319–321). In bootstrap(), drop the writeBootConfig re-sync (index.ts:251–255) and call the rule install unconditionally in place of syncKwinPipRule(settings.pipKeepOnTop) (index.ts:259).
  • src/main/kwin-rule.ts — rename the entry point to ensureKwinPipRule(); keep applyPipRule(existing, enabled) as the pure, tested core (the false arm still backs the removal round-trip test and any future uninstall). isKwinSession stays the only gate. Apply the match correction from Phase 0 if there was one.
  • src/main/ipc/handlers.ts — remove the pipKeepOnTop special case in the set-setting handler (handlers.ts:304–312) and the session/windowSystem fields from the system-info reply (handlers.ts:338–339), plus the now-unused imports.
  • src/shared/types.ts — remove pipKeepOnTop from AppSettings and DEFAULT_SETTINGS (types.ts:354–369, 412); remove session and windowSystem from SystemInfo (types.ts:321–329). No DB migration needed — getSettings merges over defaults, so a stale row is inert. Optional tidy-up in bootstrap(): DELETE FROM settings WHERE key='pipKeepOnTop' and unlink the stale boot.json.
EXIT — npx tsc --noEmit clean; app boots on Wayland with no relaunch; kwinrulesrc gains the rule on first boot of a KDE X11 session too.

PHASE 2Renderer — retire the toggle

Settings stops asking a question the app no longer has.

  • src/renderer/src/screens/Settings.tsx — remove the “Keep picture-in-picture above other windows” row (Settings.tsx:483–513). It was Wayland-gated, described the XWayland tradeoff, and wrote pipKeepOnTop.
  • Optional, small: a static line near the system info — “On KDE, a window rule keeps the floating player above full-screen windows.” If it should state fact rather than intent, have system info carry a pipRule: 'installed' | 'unavailable' field from the main process. Skip if it reads as noise.
  • Grep the renderer for any other pipKeepOnTop / windowSystem reads — the survey found none, but the grep is free.
EXIT — Settings renders without the row on both session types; no dangling references.

PHASE 3Dev tooling — un-fork the dev launcher

The dev wrapper existed only to pass the platform flag the app couldn’t apply to itself under a supervisor. With no flag to pass, dev and production stop diverging.

  • scripts/dev.mjs — delete the file; it mirrors boot.json and injects --ozone-platform=x11, nothing else.
  • package.json — point the dev script back at electron-vite dev directly.
  • Confirm scripts/soak.mjs carries no platform assumption (it was touched in the same commit; the survey found none).
EXIT — npm run dev comes up on the session’s native platform, same as production.

PHASE 4Tests — delete with the code, extend where behavior grew

Coverage follows the code: the platform-choice suite dies with the module it tests; the rule suite gains the new unconditional cases.

  • tests/boot-config.test.ts — delete (146 lines of relaunch and cache behavior with no subject left).
  • tests/kwin-rule.test.ts — rename for the new entry point; add: installs on a KDE X11 session (XDG_SESSION_TYPE=x11), installs regardless of any settings value, still a no-op off KDE. The merge/round-trip tests stand unchanged — they pin the part with a way to be wrong.
  • Run npm test and npx tsc --noEmit. The renderer PiP suites (tests/pip.test.ts, tests/renderer/pip.test.tsx) never referenced the toggle and should pass untouched — treat any failure there as a real regression, not fallout.
EXIT — full suite green.

PHASE 5Verify on the couch, then write it down

The feature is “the show keeps playing over the game”; verify it like a viewer, then make the docs tell the new, shorter story.

  • Manual pass, packaged build: fresh boot installs the rule (check ~/.config/kwinrulesrc); PiP above a full-screen game on native Wayland; fractional scaling now crisp; upgrade path — a profile that had the toggle off gets the rule installed on next boot (that is the intended behavior change).
  • docs/ui.md — replace “Staying on top, and the Wayland problem” (ui.md:120–150) and fold “Beating a full-screen window” (ui.md:152–180) into one section: the rule is the mechanism, on every session type. Sweep docs/playback.md for toggle mentions.
  • Note the uninstall story in the docs: the rule is visible and editable in System Settings → Window Management → Window Rules, and removing the app no longer auto-removes it (decision D2).
EXIT — ship it. Rollback at any point is a single revert; the rule file self-heals because the group id is fixed and the merge idempotent.

CH·04

Decisions this plan is making

  • D1Pinning becomes KDE-only, and that’s accepted. On a plain X11 session any window manager still honours Chromium’s own _NET_WM_STATE_ABOVE, so PiP clears normal windows there without our help. But on a non-KDE Wayland compositor (GNOME, Sway) there is no rule to install and no XWayland fallback anymore — PiP becomes an ordinary window. This machine is KDE; the code already gated the rule on KDE; the plan aligns the rest of the app with that reality.
  • D2No toggle means no in-app uninstall. Today, switching the setting off removes the rule. After this plan the rule is standing infrastructure, like the app’s protocol handler. It stays visible and editable in System Settings → Window Rules, and applyPipRule(…, false) survives in the codebase if a cleanup path is ever wanted.
  • D3Wayland picks where the window opens. Chromium cannot restore the PiP window’s corner on Wayland. If Phase 0 shows KWin placing it somewhere annoying, extend the rule with a position/size entry (“Apply initially” or “Remember”) rather than reintroducing client-side machinery.
  • D4This is all scaffolding for xdg-pip. KWin ships the experimental picture-in-picture protocol since Plasma 6.5; Chromium hasn’t. The day Electron’s Chromium speaks it, PiP windows are kept above natively and kwin-rule.ts is deleted whole. The plan shrinks what that future deletion has to unwind.
